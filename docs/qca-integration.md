# PawsPawns 集成 QCA（Qoder Cloud Agents）方案

## 一、两轮思考

**第一轮**候选：赛后复盘教练、实时旁白、自适应难度、每日谜题、引擎与开局库扩建、浏览器自动回归。

**第二轮**用三条硬约束筛除：

1. QCA 是**异步云端 Agent**，带工具调用的任务常在分钟级，不能进"玩家落子 → AI 回应"主循环。"实时旁白"因此降级为**离线预烧台词 + 运行时查表**，未命中退回本地模板。
2. **凭据等同管理员权限**，官方要求只在受信服务端使用，平台也无 CORS 或临时凭证机制，必须经自建代理 `/api/qca`，前端只拿结果 JSON。
3. 线上自动改难度参数会让玩家困惑且要求数据落库，违背"少即是多"，改为**离线标定、人工审核后随版本发布**。

## 二、三个方案

### 方案 A：赛后「动物教练」复盘卡（先做）

对局后把 PGN 与难度档提交 QCA，异步产出复盘卡：3 个关键转折点、每处一句狮王长老口吻的点评、一条下次建议。结算页先显示"教练正在看你的棋…"，超时只留本地统计。

- **价值**：把一局弃子变成一次学习，异步契合 QCA。
- **成本**：一个代理路由加结算页一个卡片，不动引擎。
- **风险**：点评可能出错。缓解：关键点由本地引擎给评分差，QCA 只负责措辞。

### 方案 B：每日谜题工坊

用 QCA 定期离线扫描玩家败局或自对弈局，生成"救援谜题"：残局 FEN、一到两步最佳解、动物剧情文案，产出静态 JSON 随构建发布。

- **价值**：给一次性对局游戏补上留存内容，零运行时延迟。
- **成本**：谜题格式加一个谜题模式页，复用现有棋盘。
- **风险**：唯一解需校验。缓解：本地引擎逐题验证，不通过即丢弃。

### 方案 C：引擎与难度实验室（价值最高）

让 QCA 作为开发期 Agent 做四件离线工作：把仅 7 条的开局库扩到数百条；为 `search.ts` 加迭代深化、置换表、静态搜索节点上限；用客观引擎批量标定三档 ACPL；预烧方案 A 的台词模板。

- **价值**：直接修掉实测硬伤：Lv2 中局单步 14~16 秒、Lv3 单步 77 秒、三档棋力几乎无差别。
- **成本**：不改产品形态，改动集中在引擎与数据文件，可分批合入。
- **风险**：可能引入错误着法。缓解：以基准脚本为验收门槛，回归不过不合。

**备选 D**：用 browser toolset 做发布前自动回归（需独立工具条目 + Beta header，缺一即无浏览器与预览）。

## 三、共同架构红线

- 投递事件的接口**不返回输出**；结果靠 webhook `session.status_idled` 收尾、轮询兜底（`limit` 上限 100，长任务须分页）。
- 产物三跳：`DeliverArtifacts` 交付 → 事件取 `file_id` → `/files/{id}/content` 换预签名 URL。平台无 JSON schema 约束，需自建终结标记。
- 非 GET 带幂等键，只对 429/5xx 有界重试；同 Session 并发投递返回 **409**，须串行化。
- **落子决策永远留在本地 Web Worker**，断网可玩、单步零等待。

## 四、推荐顺序

**C → A → B**。先用 C 修好等待时间与难度区分度（当前最伤体验），再用 A 补对局后的获得感，最后用 B 扩内容。
